**同一件事只交给一个工具负责。** 工具一多，最常见的问题不是缺功能，而是几个工具抢着做同一件事：一句“帮我 debug”可能被三个框架同时接住，流程前后不一致。下面这张表是我现在的分工，可信度标签说明了哪些是用了很久的，哪些还在试。

## 按阶段分工

| 阶段 | 主力 | 补充 | 人工关卡 |
|---|---|---|---|
| 起步 | 内置 `/init`、`/ainative:setup` | hookify 护栏、ui-contract（UI 项目） | 你确认 CLAUDE.md 不超过一页 |
| 规划 | `/mattpocock-skills:grill-me` | gstack `/office-hours` | 你确认 intent |
| 设计 | `/mattpocock-skills:grill-with-docs` → `to-spec` | `domain-modeling`、`prototype`、ui-contract | 产品负责人签字 |
| 开发 | Plan mode → `/mattpocock-skills:implement` | `tdd`、`to-tickets`、`wayfinder`、worktree | 工程师确认计划 |
| 测试 | `/mattpocock-skills:tdd` + gstack `/qa` | `diagnosing-bugs` | 代码所有者看证据 |
| 发布 | 内置 `/code-review` + gstack `/codex` 异构二审 | `/security-review`、gstack `/cso`、`/ship` | 人批准，写代码的 agent 不能批自己 |
| 运维 | gstack `/canary`、`/investigate` | `/ainative:harvest`、`/schedule` 园丁 | 服务负责人决定处置 |

流程引擎这一列以 Matt Pocock skills 为主。我用了大半年的 superpowers 已经停用，两者的取舍见[完整对比](/docs/workflow/superpowers-vs-matt)。

## 不建议装的

- **和内置功能重复的插件**。Claude Code 已经内置 `/code-review`、`/simplify`、`/security-review`，再装同类插件只会多一份常驻上下文、多一个抢触发的对象。
- **一次性装一整个合集**。大合集里多数 skill 你一年也用不到一次。我曾经装了 39 个插件、72 个 subagent，按最近 30 天的真实调用统计后精简到 16 个插件、19 个 subagent。见[插件不是越多越好](/docs/pitfalls/plugin-bloat)。
- **两套同时自动触发的流程框架**。要试新的，就把其中一套设为只能手动调用。见[迁移方法](/docs/workflow/migrate)。

## 怎么检查自己的工具链

```bash
claude plugin details <插件名>@<marketplace>    # 组件清单与常驻 token 成本
```

或者装好[本手册插件](/docs/reference/plugin)后运行 `/ainative:doctor`：它会统计最近各个 skill 的调用次数，指出冗余、冲突和缺失的护栏。
