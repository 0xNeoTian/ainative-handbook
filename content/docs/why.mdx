我带着几位协作者，同时运营两个组织：十几个代码仓库、几十个 agent。代码、文档、部署、日常运营，主要靠 Claude Code 完成。半年下来，攒了 70 多篇复盘。这本手册就是把这些复盘整理成**能照着做的流程、模板、规则和插件**。

## 为什么要整理

复盘越写越多，同一类坑却还在踩。

最典型的一次：本地数据库被一条破坏性的数据库命令清空之后，我给它加了三层防护：脚本先备份、命令要人工确认、hook 自动兜底。半年后一次排查才发现，三层全没了，原因只有两个：备份脚本在一次上游合并时被冲掉；权限规则和 hook 的挂载，被一个配置切换工具的一次整份覆盖一起带走，hook 脚本还在，只是没挂上。恢复手册里甚至写过检查命令，可它只是一段文字，没有任何机制去跑。（完整经过见[防护规则会悄悄失效](/docs/pitfalls/guardrails-decay)。）

问题不在于没总结，而在于**总结停留在文字里，没有变成会自动生效的东西**。所以这本手册里，能变成命令的写成命令，能变成模板的写成模板，能变成 hook 和 skill 的就做成插件。

## 和现有资料有什么不同

| 资料 | 是什么 | 本手册的关系 |
|---|---|---|
| Anthropic《AI-native SDLC playbook》 | 写给公司工程负责人的六阶段框架 | 产品篇以它为骨架，补上一个人怎么落地 |
| superpowers、Matt Pocock skills、gstack 等 | 工具：告诉你用什么 | 说明每个工具负责哪件事、怎么组合、哪些不要同时开 |
| OpenAI《Harness engineering》 | 一个团队用 agent 写完整个产品的实验 | 组织篇借用它的理念，并给出 Claude Code 里的实现 |
| **这本手册** | 一个实践者从小工具到组织的完整路径 | 每条规则都标明出处，每个建议都标了可信度 |

背后的理念另有一页：[背后的理念](/docs/reference/ideas)。

## 这本手册是怎么做出来的

用手册里的方法，做这本手册：

<Steps>
<Step>
**先拷问，再动手**。用 `/mattpocock-skills:grilling` 一轮一轮问清楚：写给谁、公开到什么程度、两个组织要不要点名、直接公开还是软上线、流程引擎怎么写。答案就是这本手册的 intent。
</Step>
<Step>
**定标准，再分工**。主编（Claude 主会话）先写好[写作标准](/docs/reference/about)和任务说明，再派 6 个子 agent 并行写作：产品线、组织与护栏、流程与模板、两组坑卡、插件。每个子 agent 只能改自己负责的文件。
</Step>
<Step>
**多道审查**。敏感信息自动扫描；三个审查 agent 分别查脱敏、事实和编辑一致性；再交给另一个模型家族独立二审。
</Step>
<Step>
**静态构建，部署到 Cloudflare**。网站、llms.txt 和插件安装包来自同一份源文件。
</Step>
</Steps>
