## 发生了什么

有一次让 agent 写一份对外材料，它没先去读现有的方案文档，凭记忆写了两版。写得很顺，读起来也像那么回事，可定位整个写偏了，几条最关键的论据也漏了：方案早已迭代了好几版，它用的还是记忆里的旧印象。我看完直接打回，让它先读完最新的方案再重写，第二版的质量明显不一样。

## 为什么会这样

记忆是快照。人的记忆停在上次认真看文档的时候；模型的知识停在训练截止日，会话里存的记忆也可能是几周前的。产品却一直在变：版本、功能、命名、对外口径。

更麻烦的是，过时的细节和准确的细节读起来一样流畅，agent 写得越顺，越不容易让人起疑。对外文档又是长期存在、会被别人引用转述的，一处错误会被复制很多次。

## 怎么做

<Steps>
<Step>

**动笔前先列出权威文档**：当前的 README、相关的 spec、最近的 ADR、CHANGELOG、官方文档。哪份算数，写之前就说清楚。

</Step>
<Step>

**把要求写进提示词**：

```text
写之前先读：README.md、docs/specs/ 下对应的 spec、docs/adr/ 里最近的决策、CHANGELOG.md。
写完附一张事实表：每个数字、版本号、名称后面写出处（文件路径或 URL）。
找不到出处的标“待核实”，不要凭印象补。
```

</Step>
<Step>

**第三方库和工具的用法查最新文档**：用 context7 这类查文档的 MCP，或者直接读官方文档，不靠模型记忆。

</Step>
<Step>

**写进 CLAUDE.md**，让每次会话都照做：写对外文档前先读权威文档，凭记忆写的内容一律标“待核实”。

</Step>
</Steps>

这本手册的写作规范里也有同一条：命令、版本号、日期和数字都要有出处，查不到就不写。
