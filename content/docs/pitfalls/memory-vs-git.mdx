## 发生了什么

我跟 agent 说：“以前聊天和预览是并排显示的。”它立刻把任务理解成“恢复旧功能”，直接动手做了一个 PR。

我看了说方向不对，它又开一个 PR 撤回。再往后一轮才去查 git 历史：这两个区域从来没有并排过。那是我脑子里的新设计，只是被我记成了“以前就有”。

## 为什么会这样

人的记忆是重建出来的。想象过很多遍的画面，会和真实用过的界面混在一起，越熟悉的产品越容易混。

agent 默认把用户的话当事实。一旦接受了“以前有过”，任务的性质就变了：“恢复”意味着去找旧实现、照旧样子做，跳过新功能本该有的设计讨论。旧实现根本不存在时，它还可能从不相干的历史代码里拼出一个“原版”。

先查证只要半分钟；按错误的前提干活，我那次白搭了一个小时、6 个 commit 和一整个 PR。

## 怎么做

<Steps>
<Step>

**先查历史，再当约束**：

```bash
git log --oneline -- <文件路径>          # 这个文件的所有提交
git log --all --oneline -S '<关键词>'    # 哪些提交加过或删过这段代码，含其他分支
git show <commit> --stat                 # 某次提交改了哪些文件
```

</Step>
<Step>

**查不到，就让人明确选**：是“记错了”，还是“这是新设计”。agent 不替人选，也不默认按“恢复”处理。

</Step>
<Step>

**选了新设计，就按新需求走**：先写 spec 再动手，不要顶着“恢复”的名义直接改（见[实质改动先留文档再动手](/docs/pitfalls/process-before-code)）。

</Step>
<Step>

**写进 CLAUDE.md**：

```markdown
- 任何人（包括我）说“之前是 X”，先用 git log 查证；查不到就按新需求处理，并向我确认
```

</Step>
</Steps>
